# 吞吐与分布指标的会话峰值行（Peak Metrics）设计

日期：2026-08-31 · 状态：已批准（用户确认八项全覆盖 + 第三行常驻形态后直接执行）

## 1. 背景与目标

`ThroughputMetrics`（同日早前设计）的两行报告都是**窗口隔离**的：速率 = 当前窗口差分、分布 = 上一区间直方图。吞吐冒烟实测暴露一个观察缺陷：**峰值转瞬即逝**——20 万行大事务只占一个统计窗口，下一窗口 `吞吐:` 归零、`分布:` 变 `n/a`，"刚才最高跑到多少"无处回看，只能翻历史日志。

本设计补一条**会话级峰值行**（第三行 `峰值:`）：自指标器创建（≈进程启动）以来的八项历史最高，每 10s 随统计 tick 常驻输出，空载窗口也保留。

## 2. 语义与口径

### 覆盖八项（与既有报告的对应关系）

| # | 指标 | 峰值定义 |
|---|---|---|
| 1 | slot 读取 bytes 速率峰值 | 历次报告窗口 `slot B/s` 的最高值 |
| 2 | slot 读取 msg 速率峰值 | 历次报告窗口 `msg/s` 的最高值 |
| 3 | 组装 tx 速率峰值 | 历次报告窗口 `组装 tx/s` 的最高值 |
| 4 | 输出 bytes 速率峰值 | 历次报告窗口 `输出 B/s` 的最高值 |
| 5 | 输出 records 速率峰值 | 历次报告窗口 `rec/s` 的最高值 |
| 6 | 输出 tx 速率峰值 | 历次报告窗口 `输出 tx/s` 的最高值 |
| 7 | 回放耗时峰值 | 历次区间直方图 `max` 的最高值 |
| 8 | 事务大小峰值 | 历次区间直方图 `max` 的最高值 |

### 口径注记

- **速率峰值粒度 = 统计窗口（≈10s）均值的会话最高**，不是亚秒瞬时值——瞬时峰值需要独立的高频采样结构，本设计不做（YAGNI，见 §6）。
- 分布峰值（#7/#8）取自各区间直方图的 `max`——正是现行报告里转瞬即逝的那个值；HDR 区间被取走后不持有，峰值在取出时刻顺手留存。
- **从未有过样本的项打 `n/a`**（逐项判定）：速率峰值在首个非零窗口出现前为无记录；分布峰值同现行的零区间语义。
- 零流量窗口不参与刷新（0 不会刷新正峰值）；时钟异常窗口（elapsed 钳 1ns）产生的病态高速率**会**入峰值——与现行速率行同一输入，不额外防御（钳制本身已是病态信号）。

## 3. 组件与接线——报告面扩展，埋点零改动

全部改动收在 `ThroughputMetrics` 一个类：

- 新增 8 个峰值字段：6 个 `double`（速率）+ 2 个 `long`（分布 max），初始 `-1` 表无记录（速率恒 ≥0、分布 max 恒 ≥1，负值即"从未"）
- `reportLines(nowNanos)` 内完成更新：窗口速率计算后逐项 `max` 刷新；区间直方图取出后用其 `max` 刷新分布峰值——**更新与报告同在 consumer 线程**（与分布写入同线程的单写者假设已成立），字段无需 volatile/atomic
- 返回值从两元素变三元素 `List<String>`——**方法签名不变**，调用方 `TransactionConsumer.maybeStats` 的 for 循环零改动自然打出第三行
- 4 处埋点调用点、`Main`、公共 API、配置面**零改动**——峰值是报告面，不是新计量

## 4. 输出格式

每 10s tick 在现有两行后追加一行 INFO，格式化器全复用（`formatBytesPerSec` / `formatCountPerSec` / `formatNanos` / `grouped`）：

```
consumer 统计: LIVE=0 HANDED_OFF=0 OUTPUTTING=0 frontierLsn=0x150a2f48   ← 现有行不动
吞吐: slot=0.0 B/s (0.0 msg/s) | 组装=0.0 tx/s | 输出=0.0 B/s (0.0 rec/s, 0.0 tx/s)   ← 现有行不动
分布: 回放耗时 n/a | 事务大小 n/a   ← 现有行不动
峰值: slot=963.0 KB/s (1,269 msg/s) | 组装=193 tx/s | 输出=5.2 MB/s (19,482 rec/s, 193 tx/s) | 耗时=1.1s | 大小=200,703 rec
```

首窗（无任何记录）整行各段 `n/a`。

## 5. 测试

- `ThroughputMetricsTest` 增例（TDD 红）：首窗峰值行各段 `n/a`；**高窗 → 空窗后峰值保留**（核心断言——峰值不随窗口翻页消失，即本设计存在理由）；分布区间 `max` 的会话留存（多个含样本窗口取最高）。
- 现有断言"两行"的用例适配为三行；`ThroughputMetricsWiringTest` 的 4 埋点断言不受影响（峰值非埋点）。

## 6. 不做的事（YAGNI）

- 亚秒瞬时峰值（需独立采样结构与线程安全的滑动窗口，观察需求未到）
- 峰值时间戳标注（"峰值出现在几点"——翻日志可定位，无独立价值）
- 破纪录独立行 / 峰值重置配置面（指标常开哲学沿用）
